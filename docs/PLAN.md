# План работ

Одна итерация = один пункт `X.Y`. Пункты выполняются по порядку внутри этапа. После итерации:
1. `npm run check` зелёный (см. [правила](rules/frontend.md#11-готовность-итерации));
2. обновлено [руководство пользователя](USER_GUIDE.md): как пользоваться новым действием + горячие клавиши, раздел помечен ✅;
3. ставится `[x]`;
4. если что-то пошло не по плану, под пунктом пишется заметка `> ...`.

Ко всем этапам применяются [правила фронтенда](rules/frontend.md), [правила бэкенда](rules/backend.md) и [дизайн-решения](DESIGN.md).

## Этап 1. Модель, бесконечный канвас, корневые блоки

- [x] **1.1 Типы и схема.** В `shared/`: `LayoutDocument` (schemaVersion, id, name, roots, labelCounter), `LayoutNode` (id, type: flex / grid / link, label, description, tag, container, self, padding, repeat, children). У корневого блока есть `canvas: { x, y, width, height | null, exportMaxWidth }`. У связи (`link`) есть `sourceId` и свои `self`. zod-схемы.
  > Отклонение от формулировки: вместо `type: flex / grid / link` у блока `type: 'block'`, а flex/grid задаёт `container.kind` (discriminated union) — так переключение flex↔grid меняет только контейнер и сохраняет остальные поля блока. Корневой блок хранится как `RootEntry { canvas, node }`, а не полем `canvas` в узле. Цвета в модели нет. Источник истины — zod 4 схемы в `shared/src/document/`, типы через `z.infer`. `parseDocument` дополнительно проверяет уникальность id узлов и что `sourceId` связи указывает на корневой блок (циклы — в 8.1); сообщения zod по-русски через локаль `ru`, переданную в сам разбор (глобальный конфиг zod не меняется). У shared свой `tsconfig.json` без DOM (typecheck в `npm run check`, по нему же линтится ESLint); тесты shared гоняет Vitest фронтенда (`include` `../shared/src/**/__tests__/**`), из `tsconfig.app.json` фронта они исключены. Внутри shared тесты импортируют через `@shared` (paths в tsconfig shared).
- [x] **1.2 Фабрики.** `createDocument` (пустой), `createRootBlock`, `createFlexNode`, `createGridNode`, `createLinkNode`. Генератор id.

- [x] **1.3 Операции над деревом.** `tree.ts`: `findNode` (по всему документу), `findParent`, `getPath`, `addChild`, `addRoot`, `removeNode`, `duplicateNode`, `moveNode` (в том числе между корневыми блоками и на канвас), `updateNode`, `isDescendant`. Чистые функции + тесты.
  > Разбивка: фасад `tree.ts` (добавление, удаление, правка, дублирование + реэкспорт) поверх `tree-query.ts` (поиск, `locateNode`), `tree-move.ts` (`canMoveNode`/`moveNode`), `tree-types.ts` и внутреннего `tree-internal.ts` (структурное разделение: копируется только путь до изменённого узла, остальное — те же ссылки). Недопустимая или пустая операция возвращает тот же объект `doc` (стор по `next === doc` не пишет историю); причину отказа дают предикаты `canMoveNode`/`canAddChild` → `TreeError | null`; `duplicateNode` возвращает `{ document, copyId }`. `updatedAt` ставит стор (1.4), функции дерева его не трогают. Корень, на который ссылаются связи, нельзя вложить в блок (`source-into-block`); `removeNode` корня удаляет и все связи на него. Подписи копий при дублировании без суффикса, копия корня встаёт справа (`x + width + 80`). При выносе вложенного блока на канвас ширина без явного `width` берётся у корня-источника. Сверх формулировки: `updateRootPlacement`, `cloneSubtree`, `findRootEntry`, `locateNode`, `canAddChild`/`canMoveNode`. Сверх плана: `moveNode` на канвас с `width <= 0` берёт ширину корня-источника (как без `width`), `addRoot` с шириной `<= 0` возвращает тот же `doc`; ключи патча со значением `undefined` в `updateNode`/`updateRootPlacement` означают «не менять»; `addRoot` принимает связи только на уже существующие корни. Циклы связей не проверяются (8.1). USER_GUIDE не менялся: новых действий пользователя нет.

Положение камеры в документе не хранится. `pagehide` дописывает отложенное сохранение. Визуально в браузере не проверялось: только `npm run check` и `npm run build`.
- [x] **5.5 Файлы.** «Сохранить в .json» и «Открыть .json» с валидацией zod и понятной ошибкой.
  > Чистая логика — `documents-files.ts` (сериализация с отступом 2 и переводом строки в конце, `<название>.layout.json` через `sanitizeFileName` из `export-file.ts`, лимит 2 МБ `IMPORT_MAX_BYTES`, разбор текста со снятием BOM, `uniqueName` с суффиксом « (2)», `prepareImport` — новый id и свежий `updatedAt`). Стор: `importDocument` (сохраняет текущий, активирует новый документ, история и камера как при переключении). Composable `use-canvas-docs-files.ts`, скрытый `input type=file` в `CanvasDocsMenu`. Тост: общий `UiToast` (автоскрытие 5 с `TOAST_DURATION_MS`, `role=alert` для ошибки, крестик), хранилище `globals/toast-store.ts`, место под тост — фрагмент `CanvasToast` (снизу по центру над тулбаром), в витрине `?ui`. Чтение файла — `globals/read-file.ts`. Отклонения: в демо выпадашка по-прежнему недоступна, поэтому сохранить демо в .json нельзя; «Не удалось сохранить» (5.4) остаётся только статусом в хедере. Визуально в браузере не проверялось.
> Ревью этапа 5: нечитаемый документ только скрывается из индекса, сырые данные `layout-canvas:document:<id>` не удаляются никогда (`hideUnreadable`; «нет данных» и «не прошли схему» различаются предупреждением в консоли). Любая запись индекса сначала перечитывает его из storage и применяет upsert/remove по id (`persistIndex(change)`); `storage`-событие обновляет список (`refreshIndex`). Undo/redo не уменьшает `labelCounter` (`Math.max`). Импорт сначала пишет документ и индекс, активирует только при успехе, иначе откат своих записей, статус и текущий документ не меняются, тост «не хватает места в хранилище браузера — удалите ненужные документы». Сохранение также на `visibilitychange` (hidden). `rename` обрезает имя (`truncateName`). Иконки-кнопки строки меню — `tabindex="-1"` (действия на F2/Delete); роль `menuitemradio` оставлена: поле переименования и кнопки подтверждения удаления живут в строке только временно, фокус при этом ставится вручную и возвращается на список. Тост ошибки не скрывается сам (только крестиком), текст ограничен `TOAST_MESSAGE_MAX_LENGTH` = 300.

## Этап 6. Панель слоёв

- [x] **6.1 Дерево слоёв.** Корневые блоки верхним уровнем, внутри рекурсивный `CanvasLayerItem`: тип, подпись, сворачивание. Выделение и ховер синхронизированы с канвасом. Клик по корневому блоку центрирует его на экране.
  > Чистая логика — `layers.ts` (значок, подпись, дети строки, `toggleCollapsed`, `expandPath`, классы), центрирование — `centerOn`/`rootRect` в `camera.ts` + `centerWorldRect` в `camera-store` (зум не меняется; если корень больше видимой области, по этой оси он прижимается к началу с отступом `FIT_PADDING`). Свёрнутые ветки — локальное состояние панели (`use-canvas-layers.ts`, provide/inject в рекурсивные `CanvasLayerItem`), не Pinia и не документ; по умолчанию всё раскрыто, выделение с канваса раскрывает предков и прокручивает к строке (`scrollIntoViewIfHidden` в `node-dom.ts`). Ховер строк обрабатывает тот же `pointermove` поля в `use-canvas-select.ts` по атрибуту `data-layer-id` (обработчик в самой строке перебивался бы сбросом ховера над панелями). Клик по вложенному блоку только выделяет. Без ролей `tree`/`treeitem` (стрелочной навигации нет): список `ul`, у строки кнопки «шеврон» (`aria-expanded`) и «выделить» (`aria-current`). Токены `$layer-indent` = 12, `$layer-toggle-width` = 18 (TOKENS.md). Проверено в браузере на демо (`?demo`): дерево, ховер, выделение, центрирование корня.
- [x] **6.2 Переименование.** Двойной клик или `F2` — по слою, по подписи блока на канвасе.
  > Общий `label-edit-store` получил место ввода `place` (`canvas` / `layers`) и `layersPickId`: клик по строке запоминает блок (`pickInLayers`), клик на канвасе сбрасывает; `F2` открывает поле в строке, если блок выбран в «Слоях» или фокус клавиатуры в строке (`renameSelected(fromLayers)`), иначе на канвасе. В строке — общий `UiTextInput` вместо кнопки выбора; клавиши поля — чистая `labelEditKeyAction` (`label-editor.ts`), общая с полем на канвасе. Двойной клик на канвасе (`dblclick` в `use-canvas-select.ts`): подписи помечены `data-label-node-id` (заголовок корня, чип, подпись листа); чип и подпись прозрачны для указателя, поэтому попадание проверяется по прямоугольнику подписи (`labelNodeIdAt` + `rectContains`). Подпись пустого листа занимает весь блок, так что двойной клик в любом месте листа переименовывает его. Проверено в браузере на демо: двойной клик в «Слоях» и на канвасе, `F2` после клика по строке.

> Ревью этапа 6: переименование в строке раскрывает свёрнутых предков редактируемого узла (раньше F2 при свёрнутом предке открывал ввод без поля и блокировал хоткеи); сворачивание ветки с открытым вводом и клик по любой строке сначала применяют ввод (кнопки строк не забирают фокус, `blur` не приходит); поле получает фокус и если строка смонтировалась уже в режиме ввода. `layersPickId` сбрасывается при любой смене выделения не кликом по строке. Строка пересчитывается только при смене своего ховера/выделения/раскрытия (отдельные computed). Переименование вынесено в `use-canvas-layer-rename.ts`, фокус поля — `focusInputIn` в `node-dom.ts`. `aria-current` только у выделенной строки. Не делалось: повторное центрирование корня при двойном клике (безвредно). Известное ограничение: нет ролей `tree`/`treeitem` и навигации стрелками (roving tabindex), у строки две остановки Tab.

## Этап 7. Drag-and-drop

Своя реализация на pointer events, без библиотек. Вся геометрия учитывает зум камеры и вынесена в чистые функции с тестами.

- [ ] **7.1 Ядро.** Состояние перетаскивания, порог 4px, призрак за курсором, отмена по `Esc`, pointer capture, пересчёт координат с учётом зума.
- [ ] **7.2 Перемещение корневых блоков** по полю за подпись.
- [ ] **7.3 Поиск приёмника.** Блок под курсором, в том числе в другом корневом. Отпустили над пустым полем — блок становится корневым. Сам перетаскиваемый блок и его потомки исключаются.
- [ ] **7.4 Вставка во flex.** Индекс по главной оси с учётом `row/column`, `reverse` и `wrap`. Тесты.
- [ ] **7.5 Вставка в grid.** Ближайший ребёнок + до/после по направлению потока. Пустой контейнер → индекс 0. Тесты.
- [ ] **7.6 Индикация и drop.** Линия-индикатор вставки, подсветка приёмника, по drop → `moveNode` + запись в историю.
- [ ] **7.7 Перетаскивание в слоях.** До, после и внутрь (по зонам строки), между корневыми блоками тоже.
- [ ] **7.8 Модификаторы.** `Alt` при отпускании копирует вместо переноса. Автопанорамирование у краёв экрана.

## Этап 8. Связи

- [ ] **8.1 Логика связей.** Режим (слияние / вложение) по подписям, проверка циклов, «кто куда подключён». Чистые функции + тесты.
- [ ] **8.2 Создание связи.** Порт у корневого блока, протягивание стрелки на цель, подсветка допустимых и недопустимых целей.
- [ ] **8.3 Стрелки.** SVG-слой поверх поля с учётом камеры, тонкие линии, подсветка у выделенного блока или связи.
- [ ] **8.4 Плашки.** Вложение — плашка «→ Название» на месте ребёнка со своими свойствами «как ребёнок». Слияние — плашка «⇄ Название», заливающая цель. Клик по плашке выделяет связь, двойной клик переходит к источнику.
