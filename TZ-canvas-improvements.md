# План к ТЗ: улучшения Layout Canvas по итогам тест-драйва

Источник: тест-драйв редактора агентом (Claude) — два документа («Лендинг кофейни», 32 блока; «Хелпдеск», 143 блока, 5 корней-компонентов) с экспортом и вёрсткой по экспорту агентом Sonnet без дополнительного контекста.

Нумерация продолжает `docs/PLAN.md` (этапы 13+). Термины — из `docs/DESIGN.md`: блок, корневой блок, связь, «как ребёнок», живое зеркало. Главный принцип не меняется: **инструмент описывает структуру для ИИ, а не дизайн**. Каждый пункт ниже либо меняет экспорт, либо помогает человеку видеть структуру.

Приоритеты: **P0** — баги и потеря данных; **P1** — сильно влияет на качество вёрстки агентом; **P2** — удобство и визуал.

## Этап 13. Баги (P0)

Каждый пункт сначала воспроизвести руками. Часть замечена при автоматизированном управлении (клики по координатам, программный фокус), поэтому возможны ложные срабатывания — они помечены.

### 13.1 Del / Backspace не удаляет блок, выделенный кликом в «Слоях»
- **Шаги:** клик по строке блока в панели «Слои» → `Delete` (и `Backspace`). Блок не удаляется; кнопка «Удалить» в «Свойствах» работает.
- **Гипотеза:** фокус остаётся на `button` строки слоя, и глобальный обработчик хоткеев пропускает событие (фильтр «фокус в интерактивном элементе»).
- **Готово, когда:** после клика по слою Del/Backspace удаляют блок; внутри текстовых полей — по-прежнему редактируют текст.

### 13.2 «Описание для ИИ» сохраняется только при потере фокуса
- **Шаги:** выделить блок → ввести описание → не уводя фокус, проверить сохранённый документ (localStorage) — описание пустое; появляется только после клика в другое место.
- **Риск:** закрытие вкладки или смена выделения в неудачный момент теряет текст. У корня это наблюдалось стабильно. В одном случае описание пропало совсем (возможно, смена выделения во время ввода — проверить).
- **Готово, когда:** описание и подпись коммитятся по вводу с debounce (~300 мс) и обязательно при смене выделения, `beforeunload`, `Ctrl+E`; статус «Сохраняется…» отражает неотправленный ввод.

### 13.3 Прокручивается вся оболочка редактора
- **Шаги:** выделить блок → Tab по полям «Свойств» до «Повтор» (или программный `scrollIntoView` у элемента панели). Вся страница сдвигается вверх: «Слои» уезжают за экран, выпадашки рисуются со смещением.
- **Гипотеза:** у корня оболочки нет `height:100vh; overflow:hidden`, и браузер прокручивает документ, чтобы показать фокус.
- **Готово, когда:** при любом фокусе/`scrollIntoView` внутри панелей `document.scrollingElement.scrollTop` остаётся 0; прокручиваются только сами панели.

### 13.4 Доступные имена у иконочных кнопок
- **Наблюдение:** в дереве доступности много `button` без имени: стрелки раскрытия в «Слоях», часть кнопок «Свойств» и тулбара.
- **Готово, когда:** у каждой иконочной кнопки есть `aria-label` (как у «Показывать подписи»). Это нужно и для доступности, и для управления редактором агентами.

### 13.5 (проверить) Выпадашка документов закрывается от смены фокуса во время подтверждения удаления
- Подтверждение «Удалить «…»?» живёт внутри меню; любое смещение фокуса закрывает меню вместе с подтверждением. Возможно, артефакт автоматизации — проверить руками.

## Этап 14. Размеры как поведение, а не пиксели (P1)

**Решение:** не убирать размеры, а сменить их роль. Агенту важно, что растягивается, а что фиксировано; точное число вторично. Превью перестаёт зависеть от чисел, и уходят проблемы с переполнением и подписями (этап 16).

### 14.1 Режим размера по каждой оси
В секции «Как ребёнок» для ширины и высоты — сегмент из трёх режимов:
- **По содержимому** (по умолчанию) — в экспорт ничего не пишется.
- **Заполнить** — `flex:1` по главной оси родителя, `align-self:stretch` по поперечной (или растяжение ячейки в grid). **Автоматически добавляет `min-width:0` / `min-height:0`** по этой оси. В тест-драйве это пришлось 5 раз писать словами в описаниях («min-width:0 обязательно, иначе…»); агент выполнил, но это должно следовать из модели.
- **Фиксированный** — число **необязательно**. Без числа экспорт пишет комментарий-намерение («фиксированная ширина, узкая колонка»), с числом — `width:360px`.

Существующие `flex` / `width` / `height` / `minHeight` мигрируют в эти режимы; свободное поле `flex` для нестандартных случаев (`0 1 480px`) остаётся в раскрывашке «Дополнительно».

### 14.2 Добавить `min-width` и `max-width`
Сейчас есть `minHeight`, но нет `minWidth` — хотя во flex-раскладках `min-width:0` нужен чаще. Если 14.1 делается позже — добавить хотя бы это поле.

### 14.3 Корень «во весь экран»
В секции «Ширина превью» у корня — флаг **«Экран целиком (100vh)»**. Экспорт: `height:100vh` у корня и строка в заголовке-комментарии «страница не скроллится целиком». Сейчас «высота превью 900» не превращается ни во что полезное, и намерение передавалось только текстом.

### 14.4 `colSpan` / `rowSpan` оставить как есть
Это структура («плитка во всю ширину»), а не дизайн. Проверить, что они доступны в UI у ребёнка grid (в модели есть).

**Готово, когда:** экспорт хелпдеска, пересобранного на новых режимах, не содержит в описаниях ни одного «min-width:0» и «flex:1» словами — всё в стилях.

## Этап 15. Структурные свойства, которых не хватает (P1)

Всё ниже в тест-драйве передавалось только словами. Это поведение раскладки, а не декор, — значит, по принципу DESIGN.md оно в модели.

### 15.1 Отступы (gap) — уже в планах автора
Предложение: токены **S / M / L** (без пикселей) для `gap`, по желанию — для `padding` контейнера. Экспорт: CSS-переменные (`gap: var(--gap-m)`) или комментарий «средний зазор». Без этого правило «отступы только через gap» агент выполняет, но значения придумывает сам.

### 15.2 Прокручиваемая область
Флаг у блока: **Прокрутка — нет / по вертикали / по горизонтали**. Экспорт: `overflow-y:auto` (+ автоматически `min-height:0`, если блок «Заполнить» в колонке). Это ключевое свойство любого интерфейса на 100vh: в хелпдеске три скролла задавались только описаниями.

### 15.3 Позиционирование
Флаг **Прилипание — нет / сверху / снизу** (`position:sticky; top:0`) и **Поверх родителя** (`position:absolute` + угол: ↖ ↗ ↙ ↘). Кейсы из тест-драйва: заголовки групп и разделитель даты внутри скролла; точка «онлайн» на аватаре.

### 15.4 Смысловой тег
Сейчас 7 раскладочных тегов. Агенту не хватало `article`, `a`, `button`, `h1–h3`, `p`, `img`, `ul/ol/li`, `dl`, `address`, `input/textarea`, `small`, `time` — всё ушло в описания («h1: …», «button primary: …»).
Варианты на выбор:
- **А (минимум):** расширить список тегов.
- **Б (рекомендую):** оставить раскладочный тег как есть и добавить отдельное короткое поле «Элемент» со списком-подсказкой (`h1`, `button`, `img`, `a`, `li`…), которое экспорт ставит в начало комментария или использует как тег листа.

### 15.5 Адаптивность (P2, обсудить)
Минимум — у grid-контейнера поле «колонки на узких экранах» (например, `3 → 2 → 1`), в экспорт — комментарием или media-запросом. Полноценные брейкпоинты — не нужны (уход в «вторую Фигму»).

## Этап 16. Холст: читаемость структуры (P2)

### 16.1 Подписи по экранному размеру (LOD)
Решать по реальному размеру блока на экране, а не по проценту зума:
- подпись помещается → как сейчас;
- не помещается по ширине → обрезать `text-overflow:ellipsis` **внутри** блока (сейчас вылезает за границу);
- блок уже ~40 px на экране → без текста, только цвет глубины и стрелка направления (→ ↓); полное имя в подсказке при наведении;
- узкий и высокий блок (рейл, ось таймлайна) → вертикальная подпись (`writing-mode: vertical-rl`).

### 16.2 Чипы не накладываются
- Чипы масштабируются вместе с холстом с нижним порогом шрифта (~9 px); ниже порога — скрываются, а не растут.
- На мелком масштабе чипы видны только у выделенного блока, у блока под курсором и у их предков.

### 16.3 Вложенность видна без подписей
- Превью-only отступ на каждом уровне (как сейчас 16/20 px, но гарантированно видимый) и полоса под подпись у контейнера.
- Пустой лист получает превью-минимум на одну строку подписи (~20–24 px). В экспорт ничего не идёт.
- Лист и контейнер различаются: пустой лист — пунктир/штриховка, контейнер — сплошная рамка.
- Цвета глубины после ~6 уровня повторяются → добавить второй признак (толщина рамки или светлота фона по уровню).

### 16.4 Переполнение показывать честно
Если (после 14.1) у блока фиксированный размер с числом и дети не помещаются: обрезать по границе, штриховка/красная полоса у края + бейдж «+N скрыто ↓», по клику — временно развернуть. Сейчас содержимое вылезает за рамку корня и перекрывает соседние корни.

Опционально — переключатель превью **«Структура» / «Пропорции»**: первый игнорирует числа (одинаковые кирпичики, режим размера — значком ↔ / ⊢360⊣), второй рисует числа и метки переполнения.

### 16.5 Повторы не раздувают превью
Повтор ×N: первая копия полностью, остальные — свёрнутые полупрозрачные «тени» в одну строку с бейджем ×N (или «колода» из 2–3 смещённых рамок). В тест-драйве «Группа ×3 → Карточка ×4» дала корень высотой 7368 px.

### 16.6 Связи
- Стрелки связей — только у выделенной связи/источника (или переключатель «все / выделенные»). При 5 компонентах и 21 вставке холст превращается в паутину.
- (Уже есть плашка `⇢ Имя` при выключенном зеркале — оставить поведение по умолчанию.)

### 16.7 Навигация по глубине
- Двойной клик по блоку → режим фокуса: поддерево изолировано, остальное затемнено; Esc — выход.
- При наведении — контур всех предков до корня.

### 16.8 Мелочи
- Значок «есть описание для ИИ» на чипе и в строке слоя — сразу видно недописанное.
- Маленький значок смыслового тега (header/nav/main/aside/footer) рядом с подписью.
- Мини-карта на мелком масштабе.

## Этап 17. Экспорт (P1)

### 17.1 Описание компонента — один раз
Сейчас описание корня-источника повторяется в каждом месте связи («Аватар» — 8 раз, «Кнопка-иконка» — 7 в хелпдеске): шум и лишние токены.
Сделать: перед деревом — блок `<!-- Компоненты: «Аватар» — …; «Кнопка-иконка» — … -->` с описаниями; на местах связей — только `<!-- компонент «Аватар» ×N -->` (+ описание самой связи, если появится).

### 17.2 Однозначный повтор
Сейчас ×N — одна обёртка с комментарием; агент сложил две кнопки-иконки в одну обёртку с двумя кнопками. Добавить машиночитаемую пометку на сам элемент (`data-repeat="2"`) и уточнить промпт: «элемент с ×N повторяется целиком N раз как соседи».

### 17.3 Промпт экспорта
- Убрать конфликт «размеры не меняй» ↔ адаптив: «фиксированные размеры и режимы растяжения сохраняй; адаптив добавляй только там, где он описан».
- Поле **«Правила документа»** (или из описания корня): экспорт подставляет его в промпт как общее правило. В тест-драйве правило «без margin у детей» было в описании корня, и агент применил его к раскладке, но не к мелочам внутри компонентов (`margin-left:6px` у счётчиков и т. п.).

### 17.4 Копирование в системный буфер
`Ctrl+C` сейчас работает только внутри приложения. Класть в системный буфер фрагмент JSON (поддерево + нужные корни-источники), а `Ctrl+V` — принимать его, в том числе из другой вкладки или документа. Побочный плюс: агент сможет передавать фрагменты в редактор.

## Не делать (зафиксировать в DESIGN.md)
- Цвета, шрифты, тени, радиусы, точные отступы в пикселях — всё, что агент не должен знать на этапе структуры.
- Полноценные брейкпоинты и варианты компонентов (primary/outline): описывать словами.
- Обязательные числовые размеры: число — всегда необязательная подсказка (этап 14).

## Предлагаемый порядок
1. Этап 13 (баги, особенно 13.2 — потеря текста).
2. 14.1–14.3 вместе с 15.1 (gap) — одна миграция модели и экспорта.
3. 17.1–17.3 — дешёвые правки экспорта, сразу заметные по качеству вёрстки.
4. 15.2–15.4.
5. Этап 16 (сначала 16.1, 16.4, 16.5 — они снимают основные проблемы читаемости), затем 17.4.

Для проверки каждого этапа: пересобрать «Хелпдеск» (генератор `layout-test/helpdesk-doc.js` в canvas-test пишет документ под текущую схему), экспортировать и отдать агенту без контекста. Критерий: в описаниях не осталось CSS-намерений, которые можно выразить свойствами, а вёрстка по-прежнему держит 100vh, три скролла и `row-reverse`.
