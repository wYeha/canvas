# Итерация 7.4 — вставка во flex

## Цель и контекст

Когда перетаскиваемый узел над flex-блоком (приёмник `{ kind: 'block' }` из 7.3), нужно знать **позицию вставки**
среди детей этого блока: индекс `0..children.length` в порядке детей документа (= порядок DOM), такой же, какой
ждёт `moveNode` в цели `{ type: 'child', parentId, index }` (индекс в **текущем** списке, до изъятия узла).
Индекс считается по главной оси с учётом `row`/`column`, `*-reverse` и `wrap` (несколько линий).

Ядро итерации — **чистая геометрическая функция** `flexInsertIndex` (новый `dnd/flex-insert.ts`, тесты Vitest).
Тонкая интеграция: индекс кладётся в приёмник (`DropTarget` блока получает поле `index`) и пересчитывается
в `use-drop-target.ts` там же, где сейчас ищется приёмник. Так 7.5 подключит grid в то же поле, а 7.6 возьмёт
готовый индекс для линии вставки и `moveNode` при отпускании.

Опора — 7.1–7.3: `dnd/drop-target.ts` (`resolveDropTarget`, `sameDropTarget`, прозрачность перетаскиваемого
поддерева), `dnd/use-drop-target.ts` (`refreshTarget` по точке страницы, post-watch камеры и документа),
`dnd/drag-store.ts` (`dropTarget`, `setDropTarget` пишет только при изменении), `node-dom.ts` (`findNodeElement`,
`clientRectOf`), `tree-move.ts` (`moveNode`: тот же родитель и `index ∈ {from, from + 1}` → тот же документ, без шага).

**Не входит** (следующие итерации): grid (7.5 — для grid-блока `index: null`), линия вставки, подсветка приёмника
и **реальный перенос в блок при отпускании** (7.6 — отпускание над блоком в 7.4 по-прежнему ничего не меняет),
«Слои» (7.7), `Alt` и автопанорамирование (7.8). Зоны «рядом с ребёнком, а не внутрь него» (у краёв детей) —
не 7.4: приёмник — по-прежнему самый глубокий блок под курсором (правило 7.3 не меняется).

## Архитектурные решения

### 1. Система координат

- Функция `flexInsertIndex` **не зависит от системы координат**: прямоугольники детей и точка указателя должны быть
  в одной системе; порядок на оси не меняется ни от сдвига, ни от равномерного масштаба.
- Интеграция берёт **координаты страницы (client)**: точка — та же `client`, что уже приходит в `refreshTarget`
  (и `lastClient` для пересчёта на смену камеры), прямоугольники — `clientRectOf(el)` (`getBoundingClientRect`).
  Плюсы: ни зума, ни `screenToWorld`, замер и точка из одного кадра; хит-тест тоже в client. `FLEX_LINE_EPSILON`
  тогда — экранные px (порядок величины субпиксельных погрешностей замера; разрыв линии всегда на целый размер элемента).
- 7.6 переведёт нужное в координаты viewport для линии сама (`toViewportPoint`), в 7.4 этого не нужно.

### 2. Оси и reverse: `flexFlow(direction)`

```ts
/** Ось на плоскости. */
export type Axis = 'x' | 'y'

/** Главная ось flex-контейнера и обратный ли порядок вдоль неё. */
export interface FlexFlow {
  main: Axis
  reverse: boolean
}
```

- Таблица `Record<FlexContainer['direction'], FlexFlow>` в модуле (типизированный ключ — не магические строки):
  `row → { x, false }`, `row-reverse → { x, true }`, `column → { y, false }`, `column-reverse → { y, true }`.
  Поперечная ось — другая (`x ↔ y`), вспомогательная `crossOf(axis)`.
- **Приём «координата потока».** Вдоль главной оси считаем координату в направлении раскладки:
  без reverse `flow = main`, с reverse `flow = −main` (отрезок `[start, end]` → `[−end, −start]`, точка `p → −p`).
  В координате потока дети **каждой линии идут по возрастанию в порядке DOM** при любом direction — поэтому
  отдельного «маппинга визуальной позиции обратно в DOM-индекс» нет: ответ сразу DOM-индекс.
- Поперечная ось не инвертируется: `wrap-reverse` в модели нет (`wrap: boolean`), линии всегда идут
  от начала поперечной оси (сверху для row*, слева для column*), в порядке DOM.

### 3. Элементы потока

```ts
/** Ребёнок flex-контейнера в координатах потока: DOM-индекс, отрезок по главной оси и по поперечной. */
interface FlowItem {
  index: number
  start: number
  end: number
  crossStart: number
  crossEnd: number
}
```

- `toFlowItems(rects, flow)`: из `rects[i]` (порядок детей документа) — элемент с `index = i`; `null`
  (ребёнок не отрисован/не нашёлся) пропускается. Нулевая ширина/высота допустима (центр = край).
- Перетаскиваемый ребёнок **на этом шаге не убирается**: его след (`canvas-node--drag-source`, прозрачность)
  остаётся в раскладке и честно занимает место — по нему корректно делятся линии.

### 4. Линии при `wrap`: `splitLines(items, wrap)`

- `wrap === false` → одна линия из всех элементов (переполнение не создаёт линий).
- `wrap === true`: обход в порядке DOM; **новая линия начинается, когда элемент начинается раньше конца
  предыдущего** по потоку: `item.start < prev.end − FLEX_LINE_EPSILON`. Обоснование: внутри линии flex кладёт
  элементы подряд, `start ≥ prev.end` (gap и `justify-content` только добавляют расстояние; margin у детей нет,
  `order` нет); первый элемент новой линии возвращается к началу оси, т. е. левее/выше конца предыдущего на
  целый размер. Сравнение с `prev.end`, а не с `prev.start`: иначе «по одному элементу в линии» (все `start`
  равны) не разделится. Нулевой элемент (`start = end = prev.end`) остаётся в линии.
- Не по поперечной оси: при `align-items: center/flex-end` элементы одной линии разной высоты имеют разные
  `crossStart`, а нулевой элемент у нижнего края касается следующей линии — разбиение «по зазору» ошибалось бы.
- У линии — поперечные границы `crossStart = min`, `crossEnd = max` по её элементам (по всем, включая след).

```ts
/** Линия flex-контейнера: элементы в порядке DOM и её границы по поперечной оси. */
interface FlowLine {
  items: FlowItem[]
  crossStart: number
  crossEnd: number
}
```

### 5. Исключение перетаскиваемого ребёнка

- После разбиения на линии из каждой линии убирается элемент с `index === skip`; линии, оставшиеся пустыми,
  удаляются. Границы линий не пересчитываются (линия, где был только след, исчезает; её полоса делится между
  соседями по п. 6).
- Почему убирать: иначе курсор над собственным следом ставил бы «до/после себя» в зависимости от половины, а без
  него ответ — `from` или `from + 1`, и `moveNode` (тот же родитель) возвращает **тот же документ, без шага**.
  Проверка: дети `[A, D, C]` в одну линию, тянем `D` (from = 1), курсор над следом `D` (между серединами `A` и `C`)
  → «до `C`» = 2 → `sameParentIndex` даёт `to = 1 = from` → без изменений. Через границу линий (wrap) тот же
  случай может дать 1 («после `A`» в конце линии) — тоже `from`. Это и есть «вернуть на то же место».
- `skip` считает вызывающий: индекс `draggedId` среди детей родителя-приёмника (`null`, если узел из другого
  контейнера, в т. ч. корень за тело над другим корнем).

### 6. Выбор линии: `pickLine(lines, crossPoint)`

- Линии идут в порядке DOM = по возрастанию поперечной оси. Граница между линиями `i` и `i + 1` — середина
  зазора: `(lines[i].crossEnd + lines[i + 1].crossStart) / 2`. Берётся первая линия, для которой
  `crossPoint < граница(i, i + 1)`, иначе последняя. Курсор выше первой линии → первая, ниже последней → последняя,
  в зазоре (gap между линиями) → ближайшая по половине зазора.
- Одна линия (нет `wrap`) — она без сравнений.

### 7. Позиция в линии: `indexInLine(line, flowPoint)`

- Первый элемент линии (в порядке DOM), у которого `flowPoint < (start + end) / 2` → ответ `item.index`
  («вставить перед ним»). Если такого нет → `last.index + 1` («после последнего в линии»).
- Ровно на середине — «после» (строгое `<`), фиксируется тестом.
- «После последнего элемента линии `i`» и «перед первым элементом линии `i + 1`» — один и тот же DOM-индекс,
  поэтому выбор линии у границы не даёт скачков индекса по смыслу.
- Курсор до первого ребёнка по потоку → его индекс (обычно 0); после последнего → `last.index + 1`
  (для последней линии — `children.length`, если последний ребёнок не `skip`).

### 8. Итоговая функция

```ts
/** Вход расчёта позиции вставки во flex-контейнер; координаты прямоугольников и точки — в одной системе. */
export interface FlexInsertInput {
  direction: FlexContainer['direction']
  wrap: boolean
  /** Прямоугольники детей в порядке документа (= DOM); `null` — ребёнок не отрисован. */
  rects: readonly (Rect | null)[]
  pointer: CanvasPoint
  /** Индекс перетаскиваемого ребёнка в этом контейнере; `null` — тянут узел из другого места. */
  skip: number | null
}

/**
 * Позиция вставки `0..rects.length` в порядке детей документа (как индекс цели `child` у `moveNode`):
 * линия — по поперечной оси, место в линии — по серединам детей вдоль потока (reverse учтён).
 */
export function flexInsertIndex(input: FlexInsertInput): number
```

- Порядок: `flexFlow` → `toFlowItems` → `splitLines` → убрать `skip` → нет линий → **`rects.length`**
  (пустой контейнер → 0; единственный ребёнок — сам перетаскиваемый → 1 = `from + 1` → без шага; все не
  замерены → в конец) → `pickLine` по поперечной координате точки → `indexInLine` по координате потока точки.
- Без Vue, Pinia и DOM; вход не мутируется.

### 9. Интеграция (граница 7.4)

- **Тип.** `DropTarget = { kind: 'block'; id: NodeId; index: number | null } | { kind: 'canvas' }`.
  `index: null` — позиция не считается (grid до 7.5, блок не отрисован). `sameDropTarget`: блоки равны, если
  равны `id` **и** `index`. Стор (`setDropTarget`) пишет по-прежнему только при изменении — теперь и при смене
  позиции внутри блока (в 7.6 это нужно линии). `dropDenied` не меняется.
- **`resolveDropTarget`** правила не меняет, для блока возвращает `index: null` (он не знает DOM).
- **`node-dom.ts` → `measureChildClientRects(parentId, childIds): (Rect | null)[] | null`**: элемент родителя —
  `findNodeElement(parentId)` (нет — `null`); его **прямые** дети-элементы с `data-node-id` (чип и подпись —
  без атрибута, пропускаются) собираются в `Map<id, Element>`; ответ по `childIds` из документа
  (`clientRectOf` или `null`). По документу, а не по порядку DOM: в момент между сменой документа и перерисовкой
  порядок мог разойтись (post-watch всё равно пересчитает).
- **`use-drop-target.ts`**:
  - `insertIndexIn(parentId, draggedId, client): number | null` — родитель из документа (`findNode`); не блок
    или `container.kind !== 'flex'` → `null`; ids детей; `measureChildClientRects`; `skip = ids.indexOf(draggedId)`
    (`-1` → `null`); `flexInsertIndex({ direction, wrap, rects, pointer: client, skip })`.
  - `refreshTarget`: `const base = resolveDropTarget(...)`; блок → `{ ...base, index: insertIndexIn(base.id,
    session.nodeId, client) }`; при необходимости вынести в `targetAt(nodeId, client)`, чтобы функции
    оставались короткими.
  - Замер — в том же месте, что хит-тест: в `pointermove` **до** `dragStore.movePointer` (раскладка чистая,
    `getBoundingClientRect` не форсирует layout), в post-watch камеры/документа, на старте и при `pointerup`.
    Стоимость — `k` замеров прямых детей приёмника на движение; дерево не обходится.
- **Отпускание** над блоком — без изменений (`nodeDropMove` → `null` для блока). Реальный перенос по
  `dropTarget.index` — 7.6.
- **Где окажется индекс по смыслу.** Курсор над самим ребёнком-блоком делает приёмником этого ребёнка (правило 7.3),
  поэтому индекс родителя считается, когда курсор в собственной области родителя: зазоры (`gap`), padding,
  пустое место линии, над плашкой связи (она не приёмник — её родитель) и над следом перетаскиваемого ребёнка.
  Это ограничение фиксируется в заметке; «зоны у краёв детей» — вопрос 7.6 (открытый вопрос 2).

### 10. Хоткеи, фокус, ховер, история, удаление, слушатели, `:style`

- Новых слушателей, хоткеев и состояния ховера нет; история не трогается (отпускание над блоком — no-op).
- Удаление родителя/детей во время жеста — post-watch документа пересчитывает цель (и индекс) по `lastClient`.
- Нового `:style`, токенов и цветов нет: frontend.md §4.4, TOKENS.md не меняются.

## Тест-план

**`flex-insert.test.ts`** — хелпер `r(x, y, w, h): Rect`; дети по 100×40, если не сказано иное:
- `flexFlow`: четыре направления → `{ main, reverse }`.
- **row**: дети на x 0/100/200; точка `x = 10` → 0; `x = 60` (за серединой первого) → 1; `x = 160` → 2;
  `x = 260` → 3; точка левее всех (`x = −50`) → 0; правее всех (`x = 900`) → 3; ровно на середине (`x = 50`) → 1.
- **row-reverse**: DOM `[A, B, C]` на x 200/100/0 (визуально C B A); `x = 280` (правее середины A) → 0;
  `x = 220` → 1; `x = 20` (левее середины C) → 3; левее всех → 3, правее всех → 0.
- **column**: те же по y (0/40/80, высота 40); **column-reverse**: y 80/40/0 — зеркально, как row-reverse.
- **wrap, 2 линии (row)**: контейнер шириной ~250: `[A(0,0), B(100,0) | C(0,50), D(100,50)]`;
  точка `(10, 20)` → 0; `(190, 20)` → 2 (после B в первой линии); `(10, 70)` → 2; `(190, 70)` → 4;
  точка в зазоре между линиями `(10, 44)` → первая линия → 0, `(10, 46)` → вторая → 2; выше всех → первая;
  ниже всех → вторая.
- **wrap + row-reverse**: линии `[A(150,0), B(50,0) | C(150,50)]` → точка левее B в первой линии → 2;
  правее C во второй → 2; левее C во второй → 3.
- **wrap + column (линии — колонки по x)**: `[A(0,0), B(0,40) | C(110,0)]` → точка справа `(120, 60)` → 3,
  `(120, 5)` → 2; `(10, 60)` → 2.
- **по одному элементу в линии** (все `x = 0`, y 0/50/100, wrap) → три линии; выбор по y.
- **без wrap** те же прямоугольники с «переносом» считаются одной линией (поперечная ось игнорируется).
- **пустой контейнер** → 0; **все `null`** (3 ребёнка) → 3; `null` посередине пропускается, индексы остальных сохраняются.
- **исключение своего ребёнка**: `[A, D, C]` на x 0/100/200, `skip = 1`, точка над следом D (и `x = 110`, и `x = 190`)
  → 2 («на месте» для `moveNode`: дополнительно проверить на фикстуре, что `moveNode` с этим индексом возвращает
  документ `toBe` тот же); точка левее середины A → 0; правее середины C → 3; единственный ребёнок и он `skip` → 1.
- **skip — единственный в своей линии (wrap)**: линии `[A | D | C]` (все `x = 0`, y 0/50/100) → точка `(60, 55)`
  (верхняя половина полосы D, правее середины A) → 1; `(10, 85)` (нижняя половина, левее середины C) → 2 — оба «на месте».
- **дробные и нулевые**: `[A(0, 0, 100.4, 40), B(100.3, 0, 100, 40)]` с wrap → одна линия; ребёнок нулевой ширины
  между двумя — в той же линии, его середина работает; все прямоугольники нулевые → точка `< 0` → 0, иначе `length`.
- Вход не мутируется (`deepFreeze` массива прямоугольников).

**`drop-target.test.ts`** — ожидания блоков с `index: null`; `sameDropTarget`: одинаковый `id` и разный `index`
→ `false`; одинаковые → `true`.
