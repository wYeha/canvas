# Итерация 7.3 — поиск приёмника

## Цель и контекст

Во время перетаскивания узла (сессия `kind: 'node'`) поле знает, что под курсором: блок-приёмник (в том числе в другом
корневом), пустое поле или «нельзя». Отпустили над пустым полем — блок становится корневым (один шаг истории).
Сам перетаскиваемый блок и его потомки приёмником не бывают.

Опора — 7.1–7.2: `dnd/drag-store.ts` (сессии `node`/`root`), `dnd/use-canvas-dnd.ts` (захват указателя держит viewport,
поэтому цель pointer-событий во время жеста — viewport, а не элемент под курсором), `dnd/dnd-geometry.ts`
(`createGrab`, `rootDragPosition`), `tree-move.ts` (`canMoveNode`, `moveNode`, `MoveTarget`).

**Не входит** (следующие итерации): индекс вставки во flex/grid (7.4–7.5), линия вставки, подсветка приёмника
и drop внутрь блока (7.6), «Слои» (7.7), `Alt`-копирование и автопанорамирование (7.8). Отпускание над блоком в 7.3
ничего не меняет; перемещение корня за заголовок (`kind: 'root'`) работает как в 7.2, приёмник для него не ищется.

## Архитектурные решения

### 1. Хит-тест: DOM даёт цепочку id, решение принимает чистая функция

- Под захватом указателя `e.target` всегда viewport, поэтому элемент под курсором ищется явно:
  `document.elementFromPoint(clientX, clientY)` — верхний элемент, принимающий указатель. Хватает одного элемента
  (не `elementsFromPoint`): призрак, оверлей выделения, оверлей поля подписи, подсказка пустого поля, чипы и подписи
  уже `pointer-events: none`, а «прозрачность» перетаскиваемого поддерева решается по цепочке предков (см. п. 2).
- Поверхность поля определяется уже готовым `isSurface(el)` (viewport или слой мира). Плавающие панели лежат в слоте
  viewport, но не в слое мира → `isSurface` ложь → **нет приёмника**. Хедер, тосты, точка вне окна (`null`) — так же.
- `nodeChainFromTarget(el)`: `el.closest(NODE_SELECTOR)`, затем `parent.closest(NODE_SELECTOR)` от `parentElement`
  до конца — порядок «самый глубокий → корень» гарантирован DOM. Заголовок корня лежит вне элемента блока,
  поэтому `closest` его не находит → отдельная ветка `rootHandleIdFromTarget` → `[rootId]`.
- `DropHit = { chain: NodeId[] } | null` (`null` — не над поверхностью поля). Чистая `resolveDropTarget(doc, draggedId, hit)`
  без DOM и Vue; так основная логика тестируется в node-окружении без `elementFromPoint`.

### 2. Правило выбора приёмника (`resolveDropTarget`)

1. `hit === null` → `null` (нет приёмника: панели, хедер, вне окна).
2. **Перетаскиваемое поддерево «прозрачно».** Если `draggedId` есть в цепочке, всё до него включительно отбрасывается
   (это сам узел и его потомки — они глубже в DOM). Без обхода дерева: O(глубина), без множества id поддерева.
   Обоснование выбора «ближайший допустимый предок», а не «нет приёмника»: под следом блока в раскладке лежит его
   родитель; в 7.4–7.6 это даст «вернуть на то же место» (индекс совпадёт, `moveNode` без шага), а не мигание
   «нельзя» каждый раз, когда курсор проходит над собственным следом. Для корня, которого тянут за тело,
   над собственным телом цепочка пустеет → это пустое поле (корень переезжает, как в 7.2).
3. Из оставшейся цепочки берётся первый id, который есть в документе и является блоком: плашка связи родителем
   быть не может (`parent-is-link`) — берётся её ближайший блок-предок; устаревшие id (DOM ещё не обновился) пропускаются.
4. Найден блок → `canMoveNode(doc, draggedId, { type: 'child', parentId, index: 0 })`: `null` → `{ kind: 'block', id }`,
   иначе → `null` (по факту — `source-into-block`: корень-источник связи нельзя вложить ни в какой блок, подниматься
   к предкам бессмысленно). `canMoveNode` — единственный источник правды, правила не дублируются.
5. Блоков в цепочке не осталось (курсор над пустым полем или над собственным корнем) →
   `canMoveNode(doc, draggedId, { type: 'canvas', at: { x: 0, y: 0 } })`: `null` → `{ kind: 'canvas' }`,
   иначе → `null` (`link-to-canvas`: плашку связи на канвас нельзя).
6. **Заголовок другого корня** = сам этот корень (`[rootId]` → блок-приёмник): заголовок — его подпись, клик по нему
   уже выделяет корень; так пользователь «попадает» в корень, даже если тот мелкий на экране. Заголовок собственного
   корня (тянут корень за тело) отбрасывается правилом 2 → пустое поле.

### 3. Тип и хранение

```ts
/** Куда сейчас упадёт перетаскиваемый узел: в блок или на пустое поле; `null` — некуда (или нельзя). */
export type DropTarget = { kind: 'block'; id: NodeId } | { kind: 'canvas' }
```

- Точка `at` в цель **не кладётся**: она меняется на каждое движение и разбудила бы всех читателей. Она считается
  один раз при отпускании из сессии (`grab`, `pointer`) и камеры.
- `dropTarget` в `drag-store.ts` (читатели — viewport сейчас, подсветка приёмника в 7.6). `setDropTarget` пишет только
  при изменении (`sameDropTarget`), поэтому движение мыши внутри одного блока стор не трогает.
- `dropDenied = session?.kind === 'node' && dropTarget === null` — булев computed; меняется только на границах.
- Сброс в `begin` и `end`: никаких «висящих» целей после отмены.

### 4. Когда пересчитывать

- **`pointermove`** сессии узла: `refreshTarget({ x: e.clientX, y: e.clientY })` в том же обработчике **до**
  `dragStore.movePointer` — Vue ещё не перерисовал призрак, раскладка чистая, `elementFromPoint` не форсирует layout.
  Последняя точка страницы хранится в composable (`lastClient`), не в сторе.
- **Камера** (пан/зум колесом без движения мыши): `watch(() => cameraStore.camera, …, { flush: 'post' })` — после того
  как слой мира перерисован с новым `transform`; если идёт сессия узла — `refreshTarget(lastClient)`.
- **Документ**: тот же post-watch по `layoutStore.document` (хоткеи во время жеста заблокированы, но цель могла исчезнуть).
  Существующий watch «узел пропал → `stop()`» остаётся.
- **Старт** (`start()` после `begin`) — первичная цель.
- **`pointerup`** — по координатам отпускания (они могут отличаться от последнего `pointermove`).
- Без rAF-троттлинга: на движение — один хит-тест, обход цепочки глубиной O(глубина) и 1–2 `findNode`/`canMoveNode` O(n).
  Дерево целиком не пересчитывается, computed узлов не будятся.

### 5. Отпускание над пустым полем

- Точка `at` = `rootDragPosition(grab.offset, pointer, camera)` (та же формула, что у корня в 7.2: под курсором
  остаётся точка захвата в масштабе 1:1, округление до целых px поля). Не левый верхний угол призрака: призрак
  уменьшен до `DRAG_GHOST_MAX_SIZE`, а блок встанет в натуральную величину — иначе крупный блок «прыгнул» бы от курсора.
  `canvas.x/y` корня — левый верхний угол блока (заголовок абсолютный, над ним), `grab.offset` замерен от того же угла.
- Ширина: вложенный блок → `width: Math.round(grab.size.width)` — блок сохраняет ширину, которую пользователь видел
  (ширина корня-источника по умолчанию в `moveNode` для карточки из страницы 1440 была бы неожиданной). `0`
  (не замерился) — `moveNode` сам возьмёт ширину источника. Корень за тело → `width` не передаётся (замер с дробной
  частью иначе менял бы ширину превью).
- Чистая `canvasMoveTarget(grab, pointer, camera, isRoot)` в `dnd-geometry.ts`; `isRoot` — `findRootEntry(doc, id) !== undefined`.
- Запись — один `layoutStore.moveNode(id, target)` → один `commit`. Корень в ту же точку — `moveNode` вернёт тот же
  документ, шага нет. Вложенный блок встаёт в конец `roots` (поведение `moveNode`), выделение остаётся на нём (id тот же).
- Над блоком — ничего (drop внутрь — 7.6). `null` (панели, связь над полем, корень-источник над блоком) — ничего.
- Порядок в `onPointerUp`: `refreshTarget(e)` → вычислить цель переноса из сессии → `stop()` → `moveNode`. Вынести
  в именованную функцию `nodeDropMove(): MoveTarget | null`, чтобы `onPointerUp` остался коротким.

### 6. Минимальная индикация — курсор «нельзя»

- Модификатор `canvas-viewport--drop-denied` (`cursor: no-drop`) при `dragStore.dropDenied`. Без него отпускание связи
  над полем или источника над блоком молча ничего не делает. Подсветка приёмника и линия — 7.6, здесь только курсор:
  ни нового `:style`, ни токенов, ни цветов.
- Риск: над панелями элементы со своим `cursor` (кнопки) могут показывать свой курсор — допустимо, проверить в браузере.

### 7. Хоткеи, фокус, ховер, история, удаление, слушатели

- Хоткеи на время жеста уже заблокированы (`isDragging`), `Esc` → `stop()` → `end()` сбрасывает `dropTarget`.
- Ховер не трогаем: во время жеста он не обновляется (7.1); подсветка приёмника — отдельное состояние в 7.6, не `hover`.
- Удаление узла во время жеста — существующий watch `stop()`; удаление цели — post-watch пересчитает цель.
- Новые слушатели не добавляются (только `watch` внутри composable — снимаются вместе с его scope).
- Фокус: `pointerdown` по-прежнему без `preventDefault`; поле подписи закрывается своим `blur` до старта.

## Риски и митигации

| Риск | Митигация |
|---|---|
| В happy-dom нет/пустой `elementFromPoint`, `getBoundingClientRect` — нули | `elementAtPoint` возвращает `null` без метода (старые тесты: отпускание без изменений); в DOM-тестах подмена `document.elementFromPoint` через `Object.defineProperty` (configurable), восстановление в `afterEach`; основная логика — в чистой `resolveDropTarget` |
| `elementFromPoint` попадает в новый перекрывающий оверлей без `pointer-events: none` | Все текущие оверлеи проверены (призрак, выделение, поле подписи, подсказка); в заметке PLAN и в шапке `node-dom` указать требование к будущим оверлеям (7.6: линия и рамка приёмника — `pointer-events: none`) |
| Пересчёт на колесо до перерисовки мира даст старый элемент | `flush: 'post'` у watch камеры |
| Корень за тело чуть сдвинули и отпустили — он переехал | Это и есть перенос на пустое поле (как 7.2), шаг отменяется `Ctrl` + `Z`, `Esc` до отпускания отменяет; см. открытый вопрос 1 |
| Ширина нового корня из дробного замера | `Math.round`; у корня ширина не передаётся |
| Стор будит читателей на каждое движение | Цель без `at`, запись только при изменении, `dropDenied` — булев computed |
| Функции `use-canvas-dnd.ts` разрастаются > 40 строк | Отдельные `refreshTarget`, `nodeDropMove`; файл уже ~210 строк — при необходимости вынести хит-тест+пересчёт в `dnd/use-drop-target.ts` (composable внутри папки dnd, подключается из `use-canvas-dnd`) |

## Тест-план

**`drop-target.test.ts`** (фикстура `__tests__/tree-fixture.ts`, `makeDoc`; цепочки задаются массивами):
- `hit === null` → `null`;
- пустая цепочка (пустое поле) для блока → `{ kind: 'canvas' }`; для плашки связи → `null`;
- цепочка `[leaf, parent, root]` другого корня → `{ kind: 'block', id: leaf }` (в другом корневом — тоже);
- плашка связи первой в цепочке → её блок-предок;
- курсор над самим узлом `[dragged, parent, root]` → `parent`; над потомком `[child, dragged, parent, …]` → `parent`;
- корень, которого тянут за тело, над собой `[x, root]` / над своим заголовком `[root]` → `{ kind: 'canvas' }`;
- корень-источник связи над блоком → `null`; над пустым полем → `{ kind: 'canvas' }`;
- id, которого нет в документе, пропускается;
- `sameDropTarget`: `null`/`null`, `canvas`/`canvas`, блоки с одним и разными id, блок/канвас.

**`dnd-geometry.test.ts`** — `canvasMoveTarget`: зум 1 и 0.5 с паном, округление `at` и `width`, `isRoot` → без `width`.

**`drag-store.test.ts`** — `setDropTarget` не заменяет объект при равной цели; `dropDenied` только для сессии `node`
с `null`; `begin`/`end` сбрасывают цель.

**`canvas-dnd.dom.test.ts`** (хелпер `hitAt(el | null)` подменяет `document.elementFromPoint`):
- над блоком другого корня → `dropTarget` = блок; над пустым полем (`elementFromPoint` → viewport) → `canvas`;
- над панелью (элемент в слоте вне мира — смонтировать со слотом) или `null` → `null`, класс `canvas-viewport--drop-denied`;
- над заголовком другого корня → этот корень;
- смена камеры без движения мыши (`useCameraStore().panBy`) пересчитывает цель (после `nextTick`);
- отпускание вложенного блока над пустым полем: он корневой, `at` по захвату, `width` — замеренная (в happy-dom замер 0 →
  ширина корня-источника; проверить именно это или подменить `getBoundingClientRect` у элемента), один шаг истории, `undo`
  возвращает на место, выделение на нём;
- отпускание плашки связи над пустым полем → документ тот же, `dropDenied` до отпускания;
- отпускание над блоком → документ тот же (существующий тест «отпускание… документ не меняется» оставить — без подмены `null`);
- корень за тело над пустым полем → переехал одним шагом (порядок `roots` тот же);
- `Esc` после наведения → `dropTarget === null`, документ тот же.
