# Итерация 7.5 — вставка в grid

## Цель и контекст

Когда перетаскиваемый узел над **grid**-блоком (приёмник `{ kind: 'block' }` из 7.3), нужно знать **позицию вставки**
среди детей: индекс `0..children.length` в порядке детей документа (= порядок DOM и авторазмещения CSS Grid),
такой же, как у цели `{ type: 'child', parentId, index }` у `moveNode` (индекс в **текущем** списке, до изъятия узла).

После 7.4 во flex это уже делает `flexInsertIndex` + `insertIndexIn` в `use-drop-target.ts`; для grid сейчас
`insertIndexIn` возвращает `null`. Итерация 7.5 добавляет симметричное ядро для grid и подключает его в тот же
контур (`dropTarget.index`, client-координаты, `measureChildClientRects`).

Формулировка плана: **ближайший ребёнок + до/после по направлению потока**; **пустой контейнер → индекс 0**;
**тесты**. Отпускание над блоком по-прежнему **no-op** до 7.6; координаты — **client**, как у flex (7.4).

Опора — 7.3–7.4: `dnd/drop-target.ts`, `dnd/use-drop-target.ts`, `node-dom.ts` (`measureChildClientRects`),
`node-style.ts` (grid: `display: grid`, шаблоны, gap; **нет** `grid-auto-flow` в модели — в превью действует
поведение браузера по умолчанию, `grid-auto-flow: row`), `shared/container.ts` (`GridContainer`).

**Не входит** (следующие итерации): линия вставки, подсветка приёмника, `moveNode` при отпускании над блоком (7.6),
зоны «у края ребёнка = вставка рядом» (7.6), «Слои» (7.7), `Alt` и автопан (7.8). Парсинг `columns`/`rows` в число
треков для геометрии **не** делаем — источник истины для позиции детей на экране только замеренные прямоугольники.

## Архитектурные решения

### 1. Направление потока grid

- В модели нет `grid-auto-flow: column` и явных линий размещения детей — только авторазмещение в порядке документа.
- Принимаем **поток по строкам** (как CSS по умолчанию): вдоль оси **X** слева направо, затем следующая строка
  (ось **Y** вниз). Это согласовано с экспортом/описанием «места» в grid и с тем, что новые grid-блоки получают
  `grid-template-columns: repeat(2, 1fr)` (`DEFAULT_GRID`).
- **До/после** относительно ближайшего ребёнка определяется **только по X**: сравнение `pointer.x` с серединой
  прямоугольника ребёнка `(left + right) / 2` — как `row` во flex без reverse (строгое `<` → «до», иначе «после»).
  Поперечная координата участвует только в выборе **ближайшего** ребёнка, не в до/после.

### 2. Ближайший ребёнок

```ts
/** Квадрат расстояния от точки до прямоугольника (0, если точка внутри). */
function distanceSqToRect(point: CanvasPoint, rect: Rect): number

/** DOM-индекс ближайшего ребёнка среди кандидатов; при равном расстоянии — меньший индекс. */
function nearestChild(rects: readonly (Rect | null)[], pointer: CanvasPoint, skip: number | null): number | null
```

- Кандидаты: все `rects[i] !== null` с `i !== skip` (перетаскиваемый ребёнок **исключается**, как `withoutSkip` во flex).
- Расстояние — до **AABB** ребёнка (как `getBoundingClientRect`): внутри rect → 0; иначе до ближайшей точки границы.
  Span (`grid-column` / `grid-row` через `colSpan`/`rowSpan`) уже входит в замер браузера.
- Нет кандидатов (пустой контейнер, все `null`, или единственный ребёнок — `skip`) → ответ **`rects.length`**
  (пустой → **0**; единственный `skip` → **1** = `from + 1` → «на место» у `moveNode`).

### 3. Итоговая функция

```ts
/** Вход расчёта позиции вставки в grid-контейнер; координаты — в одной системе (client у интеграции). */
export interface GridInsertInput {
  /** Прямоугольники детей в порядке документа; `null` — не отрисован. */
  rects: readonly (Rect | null)[]
  pointer: CanvasPoint
  /** Индекс перетаскиваемого ребёнка в этом контейнере; `null` — узел из другого места. */
  skip: number | null
}

/**
 * Позиция вставки `0..rects.length` в порядке детей документа:
 * ближайший ребёнок (без `skip`), затем до/после по оси потока (X).
 */
export function gridInsertIndex(input: GridInsertInput): number
```

- Порядок: `nearestChild` → если `null`, вернуть `rects.length` → иначе `indexBeforeAfter(nearest, pointer)`.
- Без Vue, Pinia, DOM; вход не мутируется.

### 4. Интеграция (граница 7.5 / 7.6)

- **`insertIndexIn`** (единая точка):
  - `flex` — без изменений (`flexInsertIndex`);
  - `grid` — `measureChildClientRects` + `gridInsertIndex({ rects, pointer: client, skip })`;
  - иначе / родитель не отрисован → `null`.
- **`resolveDropTarget`**, **`nodeDropMove`**, **`sameDropTarget`**, стор — без изменения поведения: отпускание над
  блоком по-прежнему не пишет документ; индекс нужен для 7.6 и для пересчёта `setDropTarget` при движении внутри
  приёмника.
- Замер и пересчёт — те же точки, что в 7.4 (`pointermove` до `movePointer`, post-watch камеры/документа).
- **Где считается индекс:** те же ограничения 7.3/7.4 — курсор над вложенным блоком выбирает **его** приёмником;
  индекс grid-родителя — в padding, gap и пустых ячейках **родителя**, над следом перетаскиваемого ребёнка.

### 5. Сознательные упрощения

- Не моделируем `justify-items` / `align-items` ≠ `stretch` отдельно — только фактические rect.
- Не поддерживаем `grid-auto-flow: column` (нет в продукте); если появится в модели — отдельная итерация.
- Не используем число колонок из строки `columns` для выбора ребёнка (сложно и хрупко для `auto-fill`); только
  геометрия, как у flex с `wrap`.

## Риски и митигации

| Риск | Митигация |
|---|---|
| Два ребёнка на одной вертикали, разный X — до/после только по X может спорить с «визуальным» порядком в колонке | Зафиксировать в JSDoc и USER_GUIDE: поток по строкам; ближайший по 2D-расстоянию, затем X; тест 2×2 сетка |
| Равное расстояние до двух детей | Тай-брейк: **меньший DOM-индекс**; тест с симметричной точкой |
| Курсор в большом gap между строками — «ближайший» далеко по Y, до/после только по X | Принять как MVP; края детей и точная привязка к ячейкам — 7.6 (открытый вопрос) |
| Span занимает несколько ячеек — середина по X смещена | Используем полный rect; поведение следует за браузером |
| Все дети `null` в замере | Как flex: `rects.length` |
| Производительность | O(n) детей приёмника на движение, без обхода дерева |
| Регресс flex | Не трогать ветку flex; прогон существующих тестов 7.4 |

## Тест-план

**`grid-insert.test.ts`** — хелпер `r(x, y, w, h)` как во flex; `at(rects, x, y, skip?)`:

- **пустой** `rects: []` → 0.
- **одна строка** `[A(0,0), B(100,0), C(200,0)]`, ширина 100: `x=10` → 0; `x=60` → 1; `x=160` → 2; `x=260` → 3;
  `x=50` (середина A) → 1; левее всех → 0; правее всех → 3.
- **две строки** (поток row): `[A(0,0), B(100,0), C(0,50), D(100,50)]`: точка `(60,10)` → 1; `(10,60)` → 2 (ближе C,
  x левее середины C); `(60,60)` → 3; в gap между A и B по y `(50,5)` — ближайший A или B, проверить детерминизм.
- **skip**: `[A, D, C]` на одной строке, `skip=1`, точка над бывшим местом D → 2; левее середины A → 0; единственный
  ребёнок и он `skip` → 1; связка с `moveNode` на фикстуре (как в flex-insert.test.ts).
- **все `null`** (3 слота) → 3; `null` посередине — индексы соседей по nearest.
- **равное расстояние**: два rect симметрично от точки — меньший индекс.
- **внутри rect** ближайшего: distance 0, до/после по X относительно середины этого rect.
- Вход не мутируется (`deepFreeze`).

**`canvas-dnd.dom.test.ts`**, describe «индекс вставки в grid»:

- Раскладка `a1` (grid): `a1x` (0,0,100,40), `a1y` (110,0,100,40); тянем `c1`, hit `a1`, движение `x=50` →
  `{ kind: 'block', id: 'a1', index: 0 }`; `x=150` → `index: 1`; `x=200` → `index: 2`.
- Тянем `a1x` над областью `a1`: над следом / между `a1y` → «на место» (`index: 1` или `2` по правилу); отпускание —
  документ тот же.
- Пустой grid: в тесте `loadDocument` с документом, где есть `block('empty', 'grid', [])` (локальная копия фикстуры
  или `updateNode` после `setup` — на усмотрение worker, главное — один сценарий `index: 0`).
- Отпускание над grid с ненулевым `index` — документ не меняет.
- Обновить тест «над grid-блоком позиция не считается» → ожидать конкретный `index` (не `null`).

## Открытые вопросы к пользователю

1. **Ось до/после.** В плане принято **только X** (поток по строкам, как CSS по умолчанию). Альтернатива: для пары
   детей в одной **колонке** (одинаковый X) смотреть **Y** (сверху вниз) — ближе к «колоночному» восприятию, но
   сложнее и не совпадает с явным `grid-auto-flow: column`. Какой вариант закрепляем?
2. **Равное расстояние до двух детей.** План: **меньший DOM-индекс**. Альтернатива: предпочитать ребёнка «по потоку»
   (кто раньше в документе при равной дистанции — то же) или сравнивать вторично по Y. Подтвердить тай-брейк.
3. **Пустой grid в DOM-тесте.** Достаточно unit-теста `[] → 0`, или обязательно сценарий в `canvas-dnd.dom.test.ts`
   (потребует локального документа с пустым grid)?
4. **USER_GUIDE.** Достаточно дополнить существующий пункт про flex абзацем про grid (без ✅), или пользователю
   важно явно разделить подпункты «во flex» / «в grid»?
5. **Граница с 7.6** (как в 7.4): подтверждаем, что в 7.5 индекс в сторе есть, но отпускание над блоком — no-op?
