# 10.6 Фронт: синхронизация документов с сервером

## Цель и контекст

Документы живут в `localStorage` (индекс + документ по ключу, автосохранение 500 мс, `documents-store.ts`). Бэкенд (10.1–10.4) отдаёт `GET/PUT/DELETE /api/documents[/:id]` по сессии. Нужно: выпадашка документов показывает документы с сервера, правки уходят на сервер с дебаунсом, `localStorage` остаётся офлайн-черновиком (без сервера всё работает как раньше).

## Архитектурные решения

1. **Local-first.** Редактор по-прежнему читает и пишет только `localStorage` (синхронно, быстро, работает офлайн). Сервер — зеркало: фоновая синхронизация сводит два набора. Выпадашка показывает локальный индекс, который синхронизация дополняет документами с сервера.
2. **Состояние синхронизации** в `localStorage` (`layout-canvas:sync`): `synced: { [id]: updatedAt }` — версия, на которой стороны последний раз совпали; `deleted: id[]` — удалённые локально, ждут `DELETE`. Ключ общий для вкладок, читается свежим на каждом проходе.
3. **Чистый план** `planSync(local, server, state)` (`documents-sync-plan.ts`) по каждому id:
   - id в `deleted`: на сервере есть → `deleteRemote`; нет → убрать из `deleted`;
   - есть с обеих сторон: `updatedAt` равны → `markSynced`; изменилась только локальная (сервер = `synced`) → `push`; только серверная (локальная = `synced`) → `pull`; обе или нет записи `synced` → побеждает более свежий `updatedAt` (last-write-wins; пользователь один);
   - только локально: есть `synced` и локальная не менялась → удалён на другом устройстве → `deleteLocal`; иначе (новый, старый документ до 10.6, или правка после удаления в другом месте) → `push`;
   - только на сервере → `pull`.
4. **Оркестратор** `documents-sync.ts` — `createDocumentsSync({ isEnabled, onRemoteChanges, onUnauthorized })`: `state` (ref: `off` / `syncing` / `synced` / `failed`), `request()` (дебаунс `SYNC_DELAY_MS`), `runNow()`, `markDeleted(id)`, `stop()`. Один проход за раз; запрос во время прохода — повтор сразу после. Проход: `GET /documents` → план → `DELETE` / `PUT` / `GET` по шагам, состояние пишется после каждого шага (обрыв не теряет прогресс). Ошибки: `unauthorized` → `onUnauthorized` (стор входа `anonymous` → страница ведёт на вход), состояние `off`; сеть / 5xx / прочее → `failed`, повтор через `SYNC_RETRY_MS`.
5. **Включение:** только при `auth.state === 'authenticated'` и не в демо. `offline` / `anonymous` — синхронизации нет, статус «Сохранено в браузере».
6. **Документы-стор** зовёт `sync.request()` после каждой успешной записи индекса (сохранение, создание, переименование, импорт, удаление) и `markDeleted` при удалении; `init` запускает проход сразу. `onRemoteChanges({ pulled, removed })`: перечитать индекс; если текущий удалён на сервере — открыть другой; если текущий скачан заново и в редакторе нет несохранённых правок (нет таймера, документ = `cleanDocument`) — загрузить его (история и камера сбрасываются, как при переключении); иначе локальная правка сохранится позже с более свежим `updatedAt` и победит.
7. **Страница** (`use-canvas-documents.ts`): `request()` при возврате на вкладку и событии `online`; `auth.state` → `anonymous` во время работы → переход на `/login?redirect=…` (правки остаются в `localStorage` и уйдут после входа).
8. **Статус в хедере** (`saveStatusLabel(status, sync)`): локальная ошибка и «Сохраняется…» — как раньше; сохранено локально + `off` → «Сохранено в браузере» (точка `muted`); + `syncing` → «Синхронизация…»; + `failed` → «Нет связи с сервером» (точка `danger`, правки в браузере); + `synced` → «Сохранено».
9. **API** `documents-api.ts`: `fetchDocumentList`, `fetchDocument`, `putDocument`, `deleteRemoteDocument` поверх `apiRequest` со схемами `documentMetaSchema` / `layoutDocumentSchema` (через `parseDocument`) из `@shared`; `404` при `DELETE` — успех. Тип `DocumentMeta` фронта — из `@shared`.

## Риски и митигации

- **Потеря несохранённой правки при скачивании текущего** — перезагрузка текущего только при чистом редакторе (митигировано в п. 6).
- **Старые документы (до 10.6) удалятся как «удалённые на сервере»** — у них нет записи `synced`, поэтому они пушатся, а не удаляются.
- **Гонка правки и пуша** — пушится то, что лежит в `localStorage` на момент шага; `synced` = `updatedAt` отправленной версии; более свежая локальная уйдёт следующим проходом (`request` во время прохода ставит повтор).
- **Две вкладки** — обе синхронизируют; состояние читается свежим, повторный PUT той же версии безвреден; индекс в выпадашке обновляется событием `storage` (есть).
- **Квота `localStorage` при скачивании** — шаг пропускается с предупреждением, проход помечается `failed` (повтор позже).
- **Конфликт правок на двух устройствах** — last-write-wins по `updatedAt`, проигравшая версия теряется. Пользователь один; записать в DESIGN как ограничение.
