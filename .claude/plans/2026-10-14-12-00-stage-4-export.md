# Этап 4. Экспорт (итерации 4.1–4.5)

## Цель и контекст

Экспорт — главный продукт инструмента: ИИ-агент по HTML-скелету должен однозначно понять **структуру и вложенность** (DESIGN «Главный принцип»). Этап даёт:
- 4.1 — чистый генератор HTML одного блока с поддеревом (стили, теги, комментарии, экранирование);
- 4.2 — комментарий-контекст для вложенного блока;
- 4.3 — экспорт нескольких и всех корней;
- 4.4 — шаблон промпта (общий для всех документов, localStorage);
- 4.5 — `ExportModal`, кнопка в хедере, `Ctrl+E`, копирование и скачивание.

Каждая итерация — отдельный worker и отдельный коммит в `main` (без push). После 4.1 и 4.2 — ревью (сложная логика). В конце каждой: `npm run check` зелёный, `[x]` в `docs/PLAN.md`, заметка `> ...` при отклонениях; USER_GUIDE обновляется в 4.4 и 4.5 (в 4.1–4.3 действий пользователя нет — указать это в заметке).

Источники: `docs/PLAN.md` (этап 4, 8.7), `docs/DESIGN.md` («Экспорт», «Связи», «Шаблон промпта», «Документы, экспорт…»), `docs/TOKENS.md` (подсветка, модалка 1040×700, `ok`/`on-ok`), `docs/rules/frontend.md`.

Существующее, на что опираемся:
- `frontend/src/scripts/pages/canvas/node-style.ts` — `styleEntries(node, parentKind)`, `toInlineStyle(entries)` (разделитель `'; '`).
- `shared/src/document/css-value.ts` — `isSafeCssValue`.
- `shared/src/document/constants.ts` — `LAYOUT_TAGS`.
- `frontend/src/scripts/pages/canvas/tree-query.ts` — `getPath`, `findNode`, `findParent`, `findRootEntry`, `locateNode`.
- `frontend/src/scripts/pages/canvas/props-child.ts` — `countGridColumns(template)`.
- `frontend/src/scripts/pages/canvas/node-dom.ts` — `measureNodeWorldRect(id, zoom)`.
- `frontend/src/scripts/pages/canvas/demo-document.ts` — `createDemoDocument()` (в выводе экспорта нет id и дат, поэтому снапшоты детерминированы).
- `frontend/src/scripts/globals/storage.ts`, `globals/constants.ts` (`layout-canvas:*` ключи).
- `UiModal` (`size="export"`, слот `footer`), `UiSegmented`, `UiTextarea`, `UiButton` (`keyshortcuts`), `UiField`.

## Архитектурные решения

1. **Код экспорта — подпапка `scripts/pages/canvas/export/`** (как `dnd/` в правилах): только чистые функции без Vue/Pinia/DOM, тесты в `scripts/pages/canvas/export/__tests__/`. Строки-шаблоны и числа — в `export/export-constants.ts` (не раздувать общий `constants.ts`). Модалка — по таблице правил: `views/modals/export-modal/ExportModal.vue`, `scripts/modals/export-modal/{export-modal.types.ts,use-export-modal.ts,...}`, `styles/modals/_export-modal.scss`.
2. **Детерминированность.** Вывод зависит только от входа: никаких id, дат, `Math.random`. Перевод строки `\n`, в конце текста ровно один `\n`. Отступ — 2 пробела на уровень. Порядок детей — как в модели, порядок свойств — как в `styleEntries`.
3. **Стиль = `styleEntries` без исключений** (то же, что превью). Для вложенного узла `parentKind` — реальный родитель (`self` выводится). Для корня `parentKind = null`. Пустой лист **не** получает редакторский min-height. Единственные export-only свойства — `max-width:<W>px; margin:0 auto` у корня с `exportMaxWidth`, добавляются **после** `styleEntries`.
4. **Защита в глубину.** Каждое значение повторно проверяется `isSafeCssValue`, имя свойства — `/^[a-z-]+$/`; небезопасное свойство отбрасывается, вместо него перед элементом выводится комментарий-предупреждение с **именем** свойства (значение не повторяем). Итоговая строка `style` дополнительно HTML-экранируется как атрибут (`& " < >`). Тег проверяется по `LAYOUT_TAGS`; чужой тег → `div` + комментарий-предупреждение. В выводе никогда нет `v-html`: предпросмотр рендерится токенами через `{{ }}`.
5. **Экранирование комментариев** (`escapeCommentText`): управляющие символы (кроме `\n` в описании) → пробел; `&` → `&amp;`, `<` → `&lt;`; затем любые два дефиса подряд разбиваются: `replace(/-(?=-)/g, '- ')` (`---` → `- - -`). Этого достаточно против `-->`, `<!--`, `--!>`. Текст всегда отделён пробелом от `<!--` и `-->`, поэтому начало `>`/`->` и конец на `-` безопасны. `>` не экранируем (читаемость для ИИ: «a > b»). Подписи — однострочные (`\r\n|\r|\n|\t` → пробел, схлопнуть пробелы, trim).
6. **Формат комментариев:**
   - подпись узла: `<!-- {label}{ ×N} — {описание} -->`; части пропускаются, если пусты; нет ни подписи, ни описания, ни повтора → комментария нет;
   - у контейнера (есть дети) комментарий стоит **строкой перед** открывающим тегом на том же отступе;
   - у листа — **внутри** тега в одну строку: `<div style="display:flex; width:120px"><!-- logo --></div>`; без комментария — `<div style="…"></div>`;
   - многострочное описание → многострочный комментарий: первая строка `<!-- {label}{ ×N}`, затем каждая строка описания с отступом +2, затем `-->` на отступе комментария. У листа с многострочным описанием тег раскрывается на 3+ строки, комментарий внутри с отступом +1 уровень. Строки описания: trim справа, крайние пустые строки отбрасываются;
   - повтор: `×N` при `repeat > 1` (элемент выводится один раз, как в 9.1);
   - корень: `<!-- Корневой блок «{label}», ширина превью {W}px{, высота превью {H}px} -->` или при `exportMaxWidth` — `<!-- Корневой блок «{label}», max-width {W}px по центру -->`; описание корня — следующими строками этого же комментария; `×N` у корня тоже в заголовке. Пустая подпись корня → `ROOT_UNTITLED_LABEL` («Без подписи»).
7. **Связи до 8.7 — заглушка-плейсхолдер** в отдельном модуле `export-link.ts`: `<div style="{selfEntries плашки}"><!-- компонент «{подпись источника}» --></div>` (тег `div`, стиль — `styleEntries(link, parentKind)`). Нет источника → `LINK_MISSING_LABEL`. В 8.7 меняется только этот модуль (подстановка вместо плейсхолдера) и планировщик корней (см. п. 9) — формат и остальные функции не трогаются.
8. **«~ширина» в контексте (4.2) — из замера превью, переданного аргументом.** Экспорт остаётся чистой функцией: `options.measuredWidths?: ReadonlyMap<NodeId, number>`. Модалка при открытии меряет выделенный узел и его родителя через `measureNodeWorldRect(id, zoom)` (координаты поля = CSS px превью, зум не влияет), округляет `Math.round`. Нет замера → строка без px (только структурное описание места). Аналитический расчёт flex/grid не делаем: дорого, неточно (fr, wrap, flex-basis) и дублирует браузер. Высоту не выводим: у пустых листей в превью редакторский min-height 48px.
9. **Несколько корней (4.3): порядок — как в `doc.roots`** (это порядок слоёв, управляемый пользователем в 6/7; позиция на поле произвольна и даёт ничьи). Отбор и роли корней — отдельная функция `planRoots(doc, rootIds)` → `ExportRootPlan[] { entry, role: 'standalone' }`; в 8.7 появится роль `'component'` (подключён связью — в «всех» не повторяется, в заголовке пометка `(компонент, подставлен в «…»)`). Заголовок корня принимает массив `extraNotes: string[]` уже сейчас (пока пустой).
10. **Шаблон промпта — настройка редактора, не документа:** `localStorage['layout-canvas:export-prompt']` (строка как есть). Нет ключа или ошибка чтения → текст по умолчанию из DESIGN. «Сбросить» **удаляет ключ** (чтобы будущие правки умолчания доходили до пользователя) — нужен `removeStorageItem` в `storage.ts`. Значение — просто строка: проверка `typeof === 'string'` (zod для одной строки избыточен; так же сделано в 3.0).
11. **Промпт в выводе** — первым комментарием (`<!-- … -->`, тот же `escapeCommentText`, многострочный формат), затем пустая строка, затем код. Пустой промпт → комментария нет. Так скопированный текст и скачанный файл — валидный HTML.
12. **«Скачать .html» — полный документ**: `<!DOCTYPE html>`, `<html lang="ru">`, `<head><meta charset="utf-8"><title>{имя документа, HTML-экранировано}</title></head>`, `<body>` + тот же текст, что копируется (с отступом +1 уровень) + `</body></html>`. Обоснование: без `meta charset` кириллица в комментариях при открытии файла ломается; ИИ полный документ читает так же хорошо, а в чат копируется фрагмент. Никаких стилей в `<head>` (README: только flex/grid/padding/размеры). Имя файла: `{имя документа}.html` для «отмеченных/всех», `{имя документа} — {подпись блока}.html` для выделенного; санитизация `[\\/:*?"<>|\x00-\x1F]` → `-`, trim, пусто → `layout`.
13. **Подсветка — своя, без библиотек**: наш вывод — узкая грамматика (doctype, комментарии, теги, атрибут `style`, строка). Токенайзер `export-highlight.ts` проходит по готовому тексту и даёт строки токенов (`tag`, `attr`, `string`, `comment`, `prompt`, `punct`, `text`); склейка токенов обязана давать исходный текст (тест). Промпт подсвечивается целиком как `prompt` (модалка знает его границы — подсвечивает две части отдельно). Цвета — токены `syntax-*` из TOKENS.md (уже есть в `_variables.scss`). Библиотека (Prism/Shiki) — лишние десятки КБ и CSS-тема вне нашей системы токенов, ради 6 видов токенов не нужна.
14. **Состояние открытия модалки** — не Pinia: `scripts/pages/canvas/use-canvas-page.ts` держит `exportOpen` и `openExport()`; `CanvasPage` передаёт `openExport` в `useCanvasHotkeys({ openExport, isBlocked })` и слушает `@export` у `CanvasHeader`; `<ExportModal v-model:open="exportOpen" />` монтируется в `CanvasPage`. Пока модалка открыта, хоткеи канваса не срабатывают (`isBlocked: () => exportOpen.value`), иначе Esc закрытия модалки одновременно поднимет выделение к родителю.

## Публичный API (контракт для всех итераций)

`frontend/src/scripts/pages/canvas/export/export-types.ts`:
```ts
type ExportScope =
  | { kind: 'selected'; nodeId: NodeId }
  | { kind: 'roots'; rootIds: readonly NodeId[] }   // «отмеченные»
  | { kind: 'all' }
interface ExportOptions {
  measuredWidths?: ReadonlyMap<NodeId, number>     // 4.2
}
interface ExportRootPlan { entry: RootEntry; role: 'standalone' }  // 8.7 добавит 'component'
```
Функции верхнего уровня:
- `exportNodeLines(doc, node, parentKind, depth): string[]` (4.1, рекурсивно, внутренняя для модулей экспорта);
- `exportRootHtml(doc, entry): string` (4.1) — корень с заголовком;
- `exportSelectedHtml(doc, nodeId, options): string` (4.2) — корень → как `exportRootHtml`, вложенный → контекст + узел;
- `exportScopeHtml(doc, scope, options): string` (4.3) — единая точка для модалки;
- `withPrompt(prompt, code): string` (4.4);
- `wrapHtmlDocument(text, title): string`, `exportFileName(docName, scope, doc): string` (4.5);
- `highlightCode(text, kind: 'code' | 'prompt'): HighlightLine[]` (4.5).

`doc` передаётся везде ради подписей источников связей и (в 8.7) подстановки.

## Риски и митигации

| Риск | Митигация |
|---|---|
| Экспорт расходится с превью | Только `styleEntries`; round-trip DOM-тест сравнивает каждый `style`; export-only свойства — лишь `max-width`/`margin` корня. |
| Инъекция через данные в обход zod (импорт старого/подделанного файла, localStorage) | Повторная проверка CSS, тега, имени свойства; экранирование атрибута и комментариев; DOM-тест на отсутствие `script`/лишних атрибутов; предпросмотр без `v-html`. |
| Слишком агрессивное экранирование портит читаемость для ИИ | Экранируем только `&`, `<` и `--` в комментариях; `>` и кириллицу не трогаем. Снапшоты показывают реальный вид. |
| Нестабильные снапшоты | В выводе нет id/дат; тест на клон с другими id; один `\n` в конце. |
| Замер ширины недоступен (узел не отрисован, тест без DOM) | `measuredWidths` необязателен; строка «Место» без px. |
| 8.7 потребует переделки формата | Плейсхолдер связи и роли корней изолированы (`export-link.ts`, `planRoots`), заголовок корня уже принимает `extraNotes`. |
| Esc закрытия модалки двигает выделение / Ctrl+E перехватывает браузер | `isBlocked` у хоткеев, `preventDefault` на Ctrl+E. |
| Clipboard API недоступен (не HTTPS, нет прав) | Fallback `execCommand`, затем сообщение и выделяемый `pre`. |
| Большие документы — тяжёлый предпросмотр | Всё `computed`, без пересчёта на ховер; подсветка линейная. При заметных тормозах — заметка в PLAN, виртуализация не в этом этапе. |
| Функции разрастаются > 40 строк | Разбиение по файлам задано выше; на ревью проверить. |
