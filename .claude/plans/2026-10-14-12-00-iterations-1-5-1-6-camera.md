# План: итерации 1.5 «Камера» и 1.6 «Канвас»

## Цель и контекст

- **1.5** — модель камеры `{ x, y, zoom }` и чистая геометрия (экран ↔ поле, зум к точке, шаги зума, вписывание прямоугольника, габариты корней) + Pinia-стор камеры. Без UI.
- **1.6** — живой канвас: слой «мира» с `transform`, точечный фон, движущийся вместе с полем, панорамирование (пробел+ЛКМ, средняя кнопка, колесо/тачпад), зум (Ctrl+колесо, pinch, хоткеи, плашка), обновление USER_GUIDE.

Дальше камера нужна: 1.7 (корни в координатах поля внутри слоя мира + замер высот корней), 6.1 (центрирование корня), 7.x (DnD: `screenToWorld`, автопанорамирование через `panBy`), 8.3 (SVG-стрелки в мировых координатах внутри того же слоя). API ниже рассчитано на это, но **реализуем только 1.5/1.6**.

**Порядок работы worker:** сначала часть 1.5 полностью (`npm run check` зелёный, PLAN отмечен) → **остановиться и отчитаться** (родитель коммитит). Затем часть 1.6 → отчёт. Если родитель разрешил делать подряд — файлы частей не пересекаются, кроме `constants.ts` и `docs/PLAN.md` (в 1.6 туда только дописываются строки).

Правила: `docs/rules/frontend.md` (логика только в `scripts/`, в `.vue` — проводка; DOM только в composable через template refs; чистые функции без Vue/Pinia + тесты в `__tests__/`; JSDoc у каждой функции, шапка у каждого файла; константы в `constants.ts`; BEM, значения из `_variables.scss`).

## Архитектурные решения

1. **Модель камеры.** `Camera { x, y, zoom }`, где `x, y` — положение начала координат поля (0,0) в экранных px **относительно левого верхнего угла viewport**, `zoom` — множитель (1 = 100%).
   - `screen = world * zoom + (x, y)`; `world = (screen - (x, y)) / zoom`.
   - Ровно соответствует CSS слоя мира: `transform: translate(x px, y px) scale(zoom)`, `transform-origin: 0 0`. Никаких пересчётов в шаблоне.
   - Все «экранные» точки в функциях — локальные координаты viewport (clientX − rect.left). Перевод clientX → локальные делает composable (DOM), а не чистые функции.
2. **Где хранится.** Отдельный Pinia-стор `camera-store.ts` (`useCameraStore`), не в документе: камера — состояние вида, не данные; нужна нескольким фрагментам (Viewport, Zoom, позже Layers/DnD/стрелки) — поэтому Pinia, а не локальный composable. В `localStorage` **не сохраняем** (камера должна быть привязана к документу, а документы и автосохранение — 5.4; заметка в PLAN). Начальная камера `{ x: 0, y: 0, zoom: 1 }`.
3. **Шкала зума:** `ZOOM_STEPS = [0.1, 0.25, 0.5, 0.75, 1, 1.5, 2, 3, 4]`, `ZOOM_MIN = 0.1`, `ZOOM_MAX = 4`. Кнопки и `Ctrl+=/-` прыгают на следующую/предыдущую ступень от текущего значения (с эпсилоном `1e-6`; со 110% вверх → 150%, вниз → 100%). Колесо/pinch — плавный множитель, затем clamp. Кнопки/хоткеи зумят **к центру видимой области**, колесо — **к курсору**.
4. **Высота корней.** `rootsBounds(roots, measuredHeights)` принимает замеры аргументом (`ReadonlyMap<NodeId, number>`): высота = `canvas.height ?? measuredHeights.get(id) ?? 0`. Стор хранит `rootHeights` (пока пустой; заполнять будет 1.7 через ResizeObserver). Пустой документ → `null` → «вписать всё» сбрасывает камеру в начальную.
5. **Вписывание с учётом плавающих панелей.** Панели всегда видимы и фиксированы (DESIGN, вариант B), поэтому вписываем в «безопасную область»: viewport минус вставки `CANVAS_SAFE_INSETS` (left = $layers-width + $panel-gap, right = $props-width + $panel-gap, bottom = $pill-height + 2·$panel-gap, top = 0) плюс отступ `FIT_PADDING = 48`. Значения дублируют SCSS — в JSDoc константы явно указать, какие SCSS-переменные она повторяет. Если безопасная область вырождается (≤ 0), берётся весь viewport. Зум «вписать всё» ограничен сверху `FIT_ALL_MAX_ZOOM = 1` (мелкая карточка не раздувается до 400%); «вписать выделенное» (1.10) будет использовать `ZOOM_MAX`. `fitRect` принимает `maxZoom` параметром.
6. **Фон двигается вместе с полем.** Точки — сетка поля, поэтому `background-position = (x, y)` и `background-size = шаг·zoom`. Чтобы при 10% не было «серой каши», шаг адаптивный: базовый `CANVAS_GRID_STEP = 16` (мир), экранный шаг `16·zoom` удваивается, пока `< GRID_MIN_SCREEN_STEP = 8`, и делится пополам, пока `> GRID_MAX_SCREEN_STEP = 32` (отношение 4 ≥ 2 — всегда сходится; деления/удвоения сохраняют выравнивание с мировой сеткой). Радиус точки остаётся фиксированным в экранных px (`$canvas-dot-radius` в SCSS). Фон рисуется на самом viewport (не на слое мира), поэтому он бесконечный.
7. **Динамические стили через `:style`.** `transform` слоя мира и `backgroundPosition/backgroundSize` viewport — вычисляемые объекты из composable (это не статичный `style=""`, правила допускают; оформление по-прежнему BEM). Отметить в заметке PLAN.
8. **Обработчики событий** — в composable `use-canvas-viewport.ts` (+ выделенный `use-canvas-pan.ts`), элементы через template refs `viewportEl`, `worldEl`. `wheel` вешается вручную через `addEventListener(..., { passive: false })` в `onMounted` (иначе нельзя `preventDefault` браузерный зум), снимается в `onBeforeUnmount`. Глобальные хоткеи — `use-canvas-hotkeys.ts` (файл, предусмотренный правилами; дальше туда добавятся F/G/Del и т.д.), подключается одной строкой в `CanvasPage.vue`. Сопоставление клавиш — чистая функция с тестами.
9. **Хоткеи по `event.code`** (а не `key`), чтобы работали в русской раскладке и с Shift (`Shift+1` даёт `key = '!'`). Ctrl = `ctrlKey || metaKey`.
10. **«Поверхность» канваса.** Панорамирование мышью и обычное колесо работают, только если `event.target` — сам viewport или внутри слоя мира. Над панелями (они лежат в слоте viewport) обычное колесо скроллит панель, клики не перехватываются. Исключение: `Ctrl+колесо`/pinch где угодно внутри viewport — всегда зум канваса + `preventDefault` (иначе зумится вся страница). Подсказка `__hint` получает `pointer-events: none`.

## Риски и митигации

| Риск | Митигация |
|---|---|
| `preventDefault` в `wheel` игнорируется (passive) → зумится вся страница | Ручной `addEventListener` с `{ passive: false }` на viewport, не через `@wheel`. Проверка п.4. |
| Ctrl+= / Ctrl+0 зумит браузер | `preventDefault` в `keydown` до действия; сравнение по `code` (`Equal`, `NumpadAdd`). |
| Залипание пробела / пана после потери фокуса | `blur` окна + `visibilitychange` + `lostpointercapture` + `pointercancel` → полный сброс. |
| Пробел активирует сфокусированную кнопку или скроллит страницу | `preventDefault` на keydown/keyup Space вне полей ввода. |
| Автоскролл Windows по средней кнопке | `preventDefault` в `pointerdown` и `mousedown` с `button === 1`. |
| Разная чувствительность мыши и тачпада для зума | `exp(-clamp(deltaY) * k)` + нормализация `deltaMode`; константы вынесены, подбор вручную. |
| Размытый текст при `scale` (1.7+) | `will-change: transform` можно убрать, если блоки мылятся после зума; отметить в отчёте, если заметно. |
| Дублирование размеров панелей в TS (`CANVAS_SAFE_INSETS`) и SCSS | JSDoc со ссылкой на SCSS-переменные; при изменении `$layers-width`/`$props-width` править оба места. Альтернатива (замер панелей из DOM) отвергнута: панели — слот, их ref недоступен viewport. |
| Пан/колесо перехватывает события панелей | Предикат `isSurface`; Ctrl+колесо — осознанное исключение. |
| Функции > 40 строк в composable | Пан вынесен в `use-canvas-pan.ts`; обработчики — отдельные именованные функции с JSDoc. |
| Рассинхрон фона и слоя мира | Оба стиля считаются из одного `camera` в одном computed-цикле; общий `CANVAS_GRID_STEP`. |
